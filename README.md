# task-view（タスクビュー）

案件フォルダごとの `タスク一覧.md` を読んで、期限ビューをブラウザに出すローカルツール。読み取り専用（md は書き換えない）。
仕事の環境で使う道具の試作を、個人環境でダミーデータを使って作り込むためのフォルダ。**中身はコードと架空のダミーデータだけ**。

続きをやるときは、まず [docs/handoff.md](docs/handoff.md) を読む（目的、現状、課題、調査結果、修正方針、受け入れ基準）。

## 会社のPCで使う

1. GitHub のこのリポジトリのページで **Code → Download ZIP** を押して、zip を落とす。
2. 展開してできた `task-view-main` フォルダを、**案件フォルダが並んでいるフォルダの中**に置く。

   ```
   プロジェクト/            ← ここにある案件フォルダの タスク一覧.md を読む
   ├─ 案件A/タスク一覧.md
   ├─ 案件B/タスク一覧.md
   └─ task-view-main/      ← 置いたフォルダ
      └─ start.bat
   ```
3. `task-view-main/start.bat` をダブルクリック。ブラウザで http://127.0.0.1:8765/ が開く。止めるときは黒いウィンドウを閉じる。

- Python 3.12 以上が要る（外部パッケージは不要）。
- task-view の中の見本データ（`sample-data/`）は、本物の案件に混ざらない。
- 新しい版にするときは、zip を落とし直して `task-view-main` を置き換える（`タスク一覧.md` は task-view の外にあるので消えない）。
- 案件フォルダに雛形を作る: `python task-view-main/app/taskview.py --init 案件C`

## 見本で試す（個人の環境）

`run.bat` をダブルクリック（`sample-data/` のダミーを読む）。ブラウザで http://127.0.0.1:8765/ が開く。

```bash
python app/taskview.py --root sample-data
```

Python 3.12 以上・標準ライブラリだけ（外部パッケージ不要）。`127.0.0.1` にだけ待ち受ける。

| 引数 | 内容 |
|---|---|
| `--root <フォルダ>` | `タスク一覧.md` を探す親フォルダ（既定は task-view フォルダの1つ上。3階層下まで探す） |
| `--port <番号>` | 待ち受けポート（既定 8765） |
| `--no-open` | ブラウザを自動で開かない |
| `--dump` | 解析結果をJSONで標準出力に出して終了 |
| `--init <フォルダ>` | そのフォルダに `タスク一覧.md` の雛形を作る（既存は上書きしない） |

- 案件が2つ以上あると、先頭に「全案件の急ぎ」タブが出る。全案件から期限切れ・今日明日・7日以内だけを1行ずつ並べる（行をクリックでメモと由来）。
- md を編集したら画面の「再読み込み」、またはタブに戻ると自動で再読み込み。
- **`app/taskview.py` を変えたら、サーバーを止めて起動し直す。** 画面（`index.html`）は毎回読み込み直されるが、パーサーは起動時のコードのまま動く。

## テスト

```bash
python -m unittest discover tests
```

期限の読み取り（`10/9`・`10月9日`・`10月上旬` など）と「要確認」「待ち」の判定を確かめる。画面は `--dump` で解析結果を見てから、案件A〜Dと「全案件の急ぎ」タブを開いて確認する。

## ダミーデータ

```bash
python tools/gen_sample.py
```

`sample-data/` の案件A〜Dを作り直す。期限は実行日からの相対なので、いつ実行しても「期限切れ／7日以内／今月中／それ以降／期限未定」が出る。手で編集した分は上書きされる。

| フォルダ | 見るもの |
|---|---|
| 案件A | 標準。グループ2つ、グループなし、延長、条件付き期限、待ち・完了 |
| 案件B | 長いタイトル、バッジが多い状態、完了だけのグループ |
| 案件C_空 | 空状態 |
| 案件D_件数多 | 20件・4グループ。密度やスクロールの確認 |

※ `タスク一覧.md` というファイル名と案件フォルダ名は、仕事の環境での実際の使い方に合わせて日本語のままにしている（リポジトリの「パスに日本語を使わない」の例外）。

## タスク一覧.md の書式

読み取る箇所は次の3つ（見出しに含まれる語で探す）。

| 見出し | 内容 |
|---|---|
| `進行中` | 表。列は グループ（任意） / タスク / 期限 / 由来 / 状況・メモ。列は見出しの名前で読むので並び順は自由 |
| `待っている` | `- 人名：内容` の箇条書き |
| `完了` | `- YYYY-MM-DD：内容` の箇条書き |

- 期限の書き方: `10/9`、`10月9日`、`2026-10-09`、`10月上旬`／`中旬`、`10月中`、`11月末`、`11月`。これ以外（「クローズ後」等）は期限未定。`（旧：10/9）` を付けると「延長」。
- メモ（またはタスク名）が `要確認：` `待ち：` で始まる文を含む、またはその語だけのとき印が付く。「承認待ちの件」のような文中の語では付かない。
- グループ列（見出しは「グループ」「プロジェクト」「チケット」のどれでも可）が無い・空なら、タスク名が `名前：内容` の形ならその名前をグループにする。
- 「待っている」「完了」の項目は、先頭に `【グループ名】` を付けると同じグループに入る。

## 送る前のチェック（このフォルダを人やサービスに渡す前に）

- 実在の会社名・人名・案件名・チケット番号・アカウントIDが含まれていないこと
- 認証情報（キー、トークン）が含まれていないこと
- 本物の `タスク一覧.md` が `sample-data/` に混ざっていないこと
